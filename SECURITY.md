# Политика безопасности

Репозиторий содержит утилиту `cio` (Container image optimizer), её релизные бинари и образ
`ghcr.io/devops-spb-ru/cio`, а также workflows GitHub Actions. Ниже — как сообщить
об уязвимости и что считается предметом отчёта.

## Поддерживаемые версии

| Версия | Поддержка |
| --- | --- |
| 0.2.x | исправления безопасности и обычные исправления |
| 0.1.x | только исправления уязвимостей |
| < 0.1 | не поддерживается |

## Как сообщить об уязвимости

- Используйте **приватный отчёт**: вкладка *Security* → *Report a vulnerability*
  (<https://github.com/DevOps-spb-ru/DevOps-Engineer-Tools/security/advisories/new>).
  Так отчёт виден только мейнтейнерам.
- Не создавайте публичный issue и не публикуйте эксплойт до выхода исправления.
- Приложите: версию (`cio --version`), способ запуска (бинарь или образ, флаги,
  `docker`/`trivy` версии), команду воспроизведения и ожидаемое поведение.
- Секреты, пароли и содержимое чужих образов в отчёт не включайте: достаточно описания.

## Что ожидать

| Этап | Срок |
| --- | --- |
| Подтверждение получения | 3 рабочих дня |
| Первичная оценка и решение о выпуске исправления | 10 рабочих дней |
| Исправление или обходной путь | зависит от серьёзности: критичные уязвимости — внеочередным патчем |
| Публичное раскрытие | после выпуска исправления; по запросу указываем автора отчёта |

## Область (что считается уязвимостью проекта)

- `cio`: разбор аргументов, чтение образов через Docker Engine API, правила анализа,
  форматы отчётов (`table`, `json`), выход за пределы допустимых путей, коды возврата `--fail-on`.
- Утечка чувствительных данных: секреты из истории сборки образа, пароли и токены в отчёте,
  запись отчёта с недостаточно строгими правами доступа.
- Релизные артефакты: бинари из GitHub Release, `SHA256SUMS`, образ
  `ghcr.io/devops-spb-ru/cio` (включая метки и состав).
- Workflows репозитория: инъекция в `run`-блоки, не пиннутые экшены, избыточные права
  `GITHUB_TOKEN`, отравление кэша.

## Вне области

- Уязвимости в сторонних компонентах: Trivy, Docker Engine, дистрибутивные пакеты базовых
  образов, сами сканируемые образы. Сообщайте в upstream; мы обновляем версии по своим
  каналам (Dependabot, `.github/dependabot.yml`).
- Требование доступа к `docker.sock`: контейнер запускается с правами root, потому что сокет
  демона принадлежит `root:root` с правами `0660`; это осознанный компромисс, описанный в
  `Container image optimizer/README.md`.
- Находки в отчёте по чужому образу (уязвимости, секреты, ошибки сборки): это результат
  анализа, а не уязвимость `cio`.

## Как защищён проект

- Зависимости обновляются Dependabot (gomod, GitHub Actions, Docker), сторонние экшены
  закреплены по SHA.
- Статический анализ: `golangci-lint` с набором `gosec`, CodeQL, `govulncheck`.
- Сканирование: Trivy (файловая система, Dockerfile, образ) в CI, отчёты — в GitHub Security.
- Секреты: проверка всей истории репозитория `gitleaks`; правило `secret-in-layer` ищет
  секреты в истории сборки. В тестовых данных — только фиктивные значения.
- Релиз: SBOM и attestations рядом с бинарями и образом, публикуется только по тегу `cio-vX.Y.Z`.
